# 钉钉侧上线操作手册（Runbook）

> 配套：`docs/dingtalk-config-package.md`（填写项）、`docs/dingtalk-integration-plan.md`（规范）
> 目标：把"升学指导协作体系"在钉钉侧上线，并与 Web 端接通读写闭环

## 0. 分工说明（重要）

| 谁做 | 做什么 |
|---|---|
| **你 / 企业管理员（在钉钉上点）** | 建应用、开权限、发布、建表/核字段、配 26 条集成自动化、拿凭证与 unionId |
| **我（在代码侧）** | 收到凭证后填 `server/.env`、开启数据源、跑通只读与写回、联调验收 |

> 我无法远程操作你的手机或钉钉账号，第 2~6 章需你本人执行；第 7 章由我完成。

## 1. 环境与身份准备

- 设备：开通应用权限、配置多维表格自动化，**建议 PC 浏览器**（手机端能做部分管理，但开发者后台体验差）；
- 身份：企业**管理员或有开发者权限的子管理员**；账号需**可编辑**目标多维表格；
- 入口：
  - 开发者后台：`https://open-dev.dingtalk.com`
  - 管理后台：`https://oa.dingtalk.com`

## 2. 建应用 + 开权限（开发者后台）

1. 登录开发者后台 → **企业内部应用** → 找到或新建「升学指导协作体系」应用；
2. 进入应用 → **凭证与基础信息** → 记下 `Client ID`、`Client Secret`（填入配置包 §1.1）；
3. **权限管理** → 批次开通以下权限（对应配置包 §3）：
   - AI 表格应用**读**权限（必须）
   - AI 表格应用**写**权限（必须）
   - 企业内部应用"调用企业 API 基本权限"（必须）
   - 通讯录 / 用户信息读取（建议，用于取 unionId）
4. **发布**该应用，并确认权限申请**审批通过**、状态为"已上线"。

## 3. 拿 4 个关键值（填入配置包 §1.2）

| 值 | 怎么拿 |
|---|---|
| `baseId` | 手机/PC 打开目标多维表格 → 复制链接，URL 里的 `baseId` 段 |
| 17 张表的真实表名/sheetId | 对照配置包 §2；拿不准用"获取所有数据表"接口列出 |
| `operatorId`（unionId） | 对表格有编辑权的账号（建议李胜）；由"查询用户详情/免登码"获取 |
| `Client ID` / `Client Secret` | 第 2 步已取得 |

> 拿到后**私发**给我或直接录入 `server/.env`（该文件已被 `.gitignore` 屏蔽）。

## 4. 建表与字段核对

1. 若尚无「节点留痕」表 → 按配置包 §4.17 新建（6 个字段）；
2. 逐表打开多维表格，对照配置包 §4：字段名一致打 `✓`，不一致记下**真实名**；
3. 缺失的字段按"建议字段名 + 类型"补齐。

> 字段名（中文）就是接口的 key，**错一个字即读写失败**。这一步决定后面能否接通。

## 5. 配置 26 条集成自动化（钉钉侧，不改动既有）

1. 入口：多维表格 → **自动化**（或管理后台 → 连接器）；
2. 按配置包 §5 清单**逐条核对**是否已存在：
   - 定时类：每日 08:00（逾期/临期/停滞/倒计时）、每日 08:30 晨报、周五 17:00 周报、每月首个工作日维护；
   - 记录触发类：节点状态变为"已完成/待家长确认"、变更 approved、约谈 completed、录取新增 offer、材料 rejected、问答新增/answered、学生档案新增（建档初始化）；
3. 缺失的补配（触发条件 + 动作照 §5）。

## 6. 应用发布上线确认

- 确认自建应用"已上线"、权限审批通过、目标账号对表格有编辑权；
- 用手机钉钉进入应用工作台，确认入口可见（家长/老师可访问）。

## 7. 交给代码接入（我执行）

凭证与字段核对完成后，我按 `docs/dingtalk-config-package.md` §7 验收清单执行：

1. 复制 `server/.env.example` → `server/.env`，填入 §1 的值、核对 §2 表名；
2. `npm run server` → `curl :8787/api/health`（P1）
   → `curl :8787/api/sheets`（核对表名）
   → `curl :8787/api/workorders`（P2 只读打通）；
3. 字段名有出入的，我只改 `server/fieldMap.js` 对应行；
4. `.env.development` 设 `VITE_USE_REAL_DATA=true` → 验证 P3 写回（节点状态/家长确认/问答答复）；
5. 通知中心接聚合结果（P5）。

## 8. 常见坑（排障速查）

| 现象 | 原因 | 处置 |
|---|---|---|
| `invalidRequest.inputArgs.invalid` | 字段名/值格式不对 | 核对配置包 §4 字段名与类型 |
| `forbidden.operationIllegal` (403) | 权限点未开 / operatorId 无表格权限 | 检查 §2、§3 |
| `invalidRequest.document.notFound` (404) | baseId 错或 operatorId 无权 | 核对 baseId 与账号权限 |
| 权限开了仍无效 | 应用未发布/未审批 | 完成 §6 |
| 只读到前 100 条 | 未分页 | 代码已循环 nextToken，无需处理 |
| token 频繁请求被限流 | 未缓存 | 代码已缓存 2h + 提前刷新 |
